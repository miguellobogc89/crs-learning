# Identification and classification (v1)

This replaces the upload flow on `feature/knowledge-first-engine-manual`.

- `POST /api/knowledge/intake` validates access, expands archives and stores originals in private storage and staging tables. Existing business-document duplicates do not block controlled tests.
- A persisted queue extracts each file once, then identifies the whole batch, then classifies the whole batch. Identification boundaries must cover every source line exactly once.
- `POST /api/knowledge/intake/:id` atomically acquires a six-minute lease and schedules one item with Next `after`. It returns 202 immediately. Results use lease-conditional writes; errors retain completed stages. Repeat POST after an error to retry the pending stage.
- The app-level queue advances pending items even when the modal closes. Closing all app tabs pauses scheduling of subsequent items; the running server item can finish. Reopening the app resumes pending items. This is not an external always-on worker. An interrupted running lease can be manually recovered after six minutes.
- The modal displays only the final JSON and a download action. Prior batches can be recovered from the folder's selector.
- Original source text is copied by code, not regenerated by the model. Provenance uses exact extracted-text lines; page numbers are not fabricated. Extraction/OCR quality and model table transcription still require real-document validation.
- Classification outputs engine, knowledge or hibrido per unit. Hibrido preserves one unit/source identity. Tables in this contract are documentary tables, not database schemas. No Engine types/records, Knowledge articles, or reconciliation are created.
- Both model calls reject incomplete output. Oversized batches (>180,000 prompt characters) fail explicitly rather than truncate. Extraction and identification remain saved for retries.
- Old import POST routes (including the former Engine controlled import) return 410. The old background provider/widget are unmounted. Previous stored imports and reusable extraction functions are retained; old internal services are no longer reachable through those execution endpoints.

No schema migration is required: staging reuses knowledge_imports and knowledge_import_files, segregated by upload_type=intake-v1 and intake_* states.

Validation: `node --test tests/knowledge/intake-contract.test.mjs tests/knowledge/intake-process.test.mjs tests/knowledge/import-extraction.test.mjs`, TypeScript and targeted ESLint. A live run requires the project's DB, private Blob and OpenAI configuration.
